# Unit 01 — Cargo Workspace and `bh-core` Domain Types

- **Milestone:** M0
- **Depends on:** —
- **Boundary:** repository skeleton and `bh-core` only. No daemon loop, no I/O, no CLI commands.

## Goal

Stand up the Cargo workspace and land the pure domain vocabulary every later
unit speaks: ids, status verbs, pane state, events, wakes, task metadata,
config, and the versioned `bhd` ↔ extension protocol. No behavior beyond type
definitions and serialization.

## Deliverables

1. Workspace root `Cargo.toml` (edition 2024, resolver 3) with members
   `crates/bh-core`, `crates/bhd`, `crates/bh`.
2. `rust-toolchain.toml` pinning `1.99.1` with `clippy` and `rustfmt`.
3. `bh-core` modules: `ids`, `time`, `status`, `pane`, `event`, `wake`, `task`,
   `config`, `protocol`.
4. `bhd` and `bh` stub binaries that build and print their protocol/version.
5. Serde round-trip tests for every persisted or protocol type.
6. `.gitignore` for `target/`.

## Design

### Ids (`ids.rs`)

Eight `String` newtypes: `RepoId`, `TaskId`, `WakeId`, `PaneId`, `TabId`,
`WorkspaceId`, `PlanId`, `SessionRef`. Each is `Display`, `From<String>`,
`From<&str>`, serde-transparent, and `Ord`/`Hash`. They are generated by one
declarative `string_id!` macro rather than eight byte-identical structs.

### Time (`time.rs`)

`Timestamp(u64)` and `Seconds(u64)`, both serde-transparent. `bh-core` never
reads the clock; callers pass timestamps in, which keeps classification and
stall checks deterministic under test.

### Status (`status.rs`)

`StatusVerb`: `Working`, `NeedsDecision`, `Blocked`, `Pr`, `Done`,
`Unknown(String)`. `Unknown` preserves the raw token so a newer crew build
cannot panic an older daemon. `as_token()` renders the protocol token;
`is_terminal()` is true only for `Done`.

### Pane state (`pane.rs`)

`PaneState`: `Idle`, `Working`, `Blocked`, `Done`, `Unknown`. These are herdr's
five agent lifecycle states, taken from `herdr --skill` (`unknown` means
"present but unclassifiable", not "empty"). Whether bulkhead also needs an
explicit "pane gone / no agent" state is deferred to Unit 10, where pane events
are subscribed.

### Events (`event.rs`)

`Event`: `StatusLine`, `PaneStateChanged`, `PlanArrived`, `AwayChanged`,
`WakeAck`, `Tick`, `Shutdown`. Each maps to exactly one future event source in
`bhd`. It is intentionally not serializable.

### Wakes (`wake.rs`)

`Wake { id, repo, task: Option<TaskId>, kind, summary, created_at }`.
`WakeKind`: `PlanInbox`, `NeedsDecision`, `Blocked`, `PrOpened`, `TaskDone`,
`TaskStalled`, `CrewGone`, `OrchestratorRevived`, `AwayBrief`. These are derived
from the feature list (trips, stalls, away-mode, revival) and are the one set
most likely to need review.

`WakeRecord` is the line type for append-only `wakes.jsonl`:
`Wake { wake }` or `Delivered { id, at }`. Recording delivery as a second
appended line keeps the file append-only (invariant 3) instead of rewriting a
`delivered` flag in place.

### Task (`task.rs`)

`Task` is the typed `meta.toml`: id, repo, title, worktree, tab, pane, session,
optional PR URL, created/updated timestamps. Work state is *not* stored here;
the classifier derives it from the status log.

### Config (`config.rs`)

`Registry { repos: BTreeMap<RepoId, RegistryEntry> }` and
`RepoConfig { delivery, max_crew, stall_after, rebase_after, away, skills, yolo }`.
`DeliveryMode`: `NoMistakes` (default), `DirectPr`, `Local`. `AwayPolicy { push }`.
Defaults: `max_crew = 3` and `stall_after = 20m` follow the context;
`rebase_after = 1h` is a provisional guess awaiting a real value.

### Protocol (`protocol.rs`)

`Envelope { version, message }` with `ProtocolMessage` tagged by `type`:
`Hello { repo, pid }`, `Wake { wake }`, `Ack { wake }`, `Error { message }`.
`PROTOCOL_MAJOR = 1`, `PROTOCOL_MINOR = 0`. `Envelope::decode` rejects any
unknown major with `ProtocolError::UnsupportedVersion` (invariant 10);
`encode` emits one newline-terminated JSON line. `Envelope` deliberately does
not use `#[serde(flatten)]`, which is fragile with internally tagged enums.

## Out of Scope

- `classify`, the status-line parser, and stall logic (Unit 02).
- Any file reading/writing, registry load/save, agent-folder building (Unit 03).
- Socket transport and wake batching (Unit 09).
